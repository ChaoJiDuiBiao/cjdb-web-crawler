# Notion 保存位置选择

## 当前交互

- 初始加载和名称搜索直接展示数据源列表。同一数据库中的多个源独立展示，仅按数据源 ID 去重，不包装成数据库对象。
- 点击数据源实时检查字段，无冲突直接成为保存目标；用途提醒和字段冲突在该行下方展示。实际写入仍需点击底部保存。
- 列表直接使用搜索返回的名称、创建日期、字段定义。同名数据源附加短 ID 便于区分；详情可在 Notion 中核对。
- 最近使用按作品、账号各保留最多六项，复用当前搜索的字段信息，或显示上次使用时保存的字段数量并标注。旧快捷项没有元信息也可直接点选，不自动请求详情。
- 搜索框支持名称、数据库 URL、Data source ID。数据库 URL 解析一次后直接列出其源；源 ID 直接定位该源。仅 ID 查询遇到 404 才尝试数据库 ID，权限或限流错误不能误报为空列表。

## 请求与性能

名称原样交给现有 Notion 搜索接口，不承诺与 Notion 自身不同的名称匹配规则。普通列表每页仅一次搜索请求；不查询父数据库，不增加固定等待，不自动统计行数。保留接口分页游标和加载、搜索状态提示。

展开“查看详情”展示已有字段；点击“读取行数与信息”才请求行数，必要时补齐字段信息。每次统计最多读取 100 行，后续页由用户继续统计。行数只代表 Token 可读取的数据。点击数据源直接选中，不请求字段详情；用途提醒读取本地历史。实际保存时再执行实时字段兼容性检查，阻止不兼容写入。

## 验证

测试使用模拟接口，覆盖搜索请求次数、同库不同源保留、分页、链接与源 ID、字段复用、按需统计、最近使用、用途与字段冲突及实际保存流程。真实 Notion 网络耗时与授权范围仍取决于用户环境。
