# 存储体验：四轮审视与决策

后续层级修订见[数据库与数据源选择](NOTION-SELECTION.md)，数据库和数据源各自展示创建日期。以下保留本轮审视决策过程。

2026-09-07。审视对象是正式 WXT 扩展；早期 HTML 原型只作为视觉参考。每轮从用户、设计师、产品经理、开发者四个角度质疑，依据任务范围、交互证据和维护成本筛选。

## 第一轮：流程是否足够清楚

| 视角 | 质疑 | 决策与落实 |
| --- | --- | --- |
| 用户 | 为什么要理解多个连接，找不到 Token 入口怎么办？ | 采纳：存储源下拉选择，Notion 未配置时直接引导输入唯一全局 Token。 |
| 设计师 | 飞书与 Notion 的表单混在一起是否分散注意力？ | 采纳：配置弹窗按来源生成字段，Notion 只显示 Token；只有保存和取消。 |
| 产品经理 | 第三方历史采集是否偏离“采集当前页面”的定位？ | 采纳：删除历史 Crawler、历史组件、API 工具、后台消息处理、域名权限、凭据表单及文档。 |
| 开发者 | 删除功能会不会破坏已有采集记录？ | 部分采纳：删除执行路径，保留旧记录的类型与导出兼容；不清空用户数据或旧存储键。 |

## 第二轮：选库信息是否可信

| 视角 | 质疑 | 决策与落实 |
| --- | --- | --- |
| 用户 | “用途未确认”有什么用？我需要知道表何时创建、字段和行数。 | 采纳：卡片展示数据库创建日期、当前数据源字段数和可访问的行数，支持展开字段名。用途提醒仅在选择后存在冲突时显示。 |
| 设计师 | 信息变多后，长库名和字段是否挤成一团？ | 采纳：主弹窗最大宽度 920 px，单列全宽卡片，库名换行、选择标记靠右，字段区域限高。 |
| 产品经理 | 是否应该自动统计所有库的精确总行数？ | 不采纳全量自动扫描：只自动读取可见卡片的一页（最多 100 条），未结束明确标注“至少 N 行”，提供继续统计，避免大量请求拖慢选择。 |
| 开发者 | 分页、无权限和失败会不会被误报为 0 行？ | 采纳：保留游标，分页累计；失败单独提示并允许重试；拒绝无效分页游标。统计失败不阻塞实时字段检查与选库。 |

数据库与数据源日期不能混淆：日期取父数据库的 `created_time`，字段和行数针对实际选中的数据源。Notion 的查询结果分页返回，不能用第一页长度推断完整总量。依据：[数据源对象](https://developers.notion.com/reference/data-source)、[查询数据源](https://developers.notion.com/reference/query-a-data-source)。统计代表当前 Token 的可读记录，外部修改不保证跨分页快照一致。

## 第三轮：状态和滚动是否可靠

| 视角 | 质疑 | 决策与落实 |
| --- | --- | --- |
| 用户 | 保存飞书凭据后怎么回到了 Notion？从本地设置好 Notion 又该去哪？ | 采纳：配置弹窗回传实际保存的来源，保存返回该来源；取消保留之前选择。回归测试发现并修复了后者。 |
| 设计师 | 仅给列表加滚动条，是否仍会挤出底部区域？ | 采纳：检查真实 Chromium 截图后调整弹窗内部高度分配，列表消化剩余空间；极矮视口保留外层滚动以保证控件可达。 |
| 产品经理 | 搜索和“最近使用”应不应该合并成一个列表？ | 不采纳：搜索用于发现全部已授权库，最近使用继续按作品和账号隔离，避免破坏已经确认的快捷选择逻辑。 |
| 开发者 | 快速切换来源、刷新或关闭后，旧请求是否污染当前 UI？ | 采纳：保留请求序号校验，元信息组件卸载后丢弃响应；关闭后卸载卡片；刷新重新挂载卡片读取元信息。 |

## 第四轮：代价与边界是否合理

| 视角 | 质疑 | 决策与落实 |
| --- | --- | --- |
| 用户 | 应不应该直接免填所有平台凭据？ | 暂缓 OAuth：本轮只简化首次配置，需要独立授权服务的免 Token 方案另行设计。 |
| 设计师 | 为了干净是否应该隐藏所有滚动条、删除取消按钮？ | 不采纳：列表可聚焦、支持键盘滚动，保留明确的取消入口。右上角关闭仅从配置弹窗移除。 |
| 产品经理 | 是否要顺便删除所有旧字段、所有旧配置和历史任务？ | 不采纳：这不帮助当前页面采集，反而会损坏用户已有资产。仅删除废弃功能和对应资料。 |
| 开发者 | 元信息请求会不会突发限流，密钥会不会出现在网页 DOM？ | 采纳：可见卡片懒加载、元信息请求串行并间隔 400 ms；凭据仍在扩展源 iframe 输入，向父页面只发送状态和存储源，不发送密钥。统计请求失败保留重试。 |

## 验证与限制

- 类型检查、生产构建、单元与真实扩展浏览器回归覆盖：来源切换、配置取消与保存、单 Token、权限与分页、内部滚动、旧数据迁移、先采集后预览、保存与重试。
- 浏览器与外部接口使用隔离模拟环境，没有对真实 Notion / 飞书账号写入。
- 未增加长期行数缓存；重新搜索或刷新会重新读取，避免把旧数量冒充当前数据。
- 元信息队列只约束自身请求，不保证与其他客户端或本扩展写入请求合计不会触发 Notion 限流。失败提示重试。
- 已发出的统计读取不会取消远端请求；关闭或切换后丢弃结果，不改变当前页面状态。
